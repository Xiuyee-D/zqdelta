# 资源保留与清理

这是长期维护规则，阶段性清理结果集中在 [开发阶段总览](DEVELOPMENT_STAGES.md#六发布准备与维护)。不在本文逐次登记文件删除或开发过程；需要追溯时查看 Git 差异和本地验收资料。

## 始终保留

- 已发布的中英文栏目、真实项目、博客元数据及单份中文笔记正文，稳定地址和配对键。
- 真实头像、项目／论文图、全部博客原图及封面。未展示的两张服务器原图仍属于用户输入。
- Academic Sans、字体及 Blue Topaz 许可、来源说明和源 TTF 缓存。旧完整 WOFF2 继续作为字形／排版验收对照；生成器写入缓存的临时分片可以清除。
- 当前 CAD 查看器、模型、海报及私有源码归档 `.dev-tools/archives/voice-terminal-r4-source.tar.gz` 和 manifest。归档是已移除独立 CAD 工程的重建来源，清理前必须校验完整性；细节见 [CAD 说明](VOICE_TERMINAL.md)。
- `.dev-tools/olfactory-project-import/` 的必要原稿、原图、下载元数据与既有导入凭据。
- 私有备用 CV、教学和双语独立论文；启用前校对真实信息和发布允许名单。404 是已启用的双语辅助页面，继续保留。
- 许可证、Git 历史、依赖锁文件、覆盖审计及实际使用的构建／验证入口。

CAD 源归档和食品项目输入不随 Git 克隆复制，换机需单独迁移；网站的运行、构建和普通回归不依赖这些私有原件。

## 可重建资料

| 对象                        | 处理方式                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------- |
| `_site/`、Jekyll 缓存       | 正式构建可以重建；当前验收完成后可保留供复核                                            |
| `.dev-tools/browsers/`      | 按锁定的 Playwright 版本下载，日常测试可复用                                            |
| 可选 CAD／字体虚拟环境      | 普通站点开发不需要；删除前确认源归档和依赖说明可用                                      |
| 字体生成中间文件            | 仅清除 `.dev-tools/font-source/academic-sans-*.woff2`；保留源 TTF、许可与旧完整字体对照 |
| `.dev-tools/quality-tools/` | 可选审计工具缓存，由 `bin/dev audit-setup` 重建，正常维护可复用                         |
| `.dev-tools/test-results/`  | 每个套件／引擎保留当前报告与同名截图，重跑覆盖，不按开发轮次建立目录                    |
| 历史站点副本、旧日志及截图  | 当前回归完成、独有输入已分离后按目录删除                                                |
| 项目 Docker 镜像            | 可重建；不执行全局 prune，需要回收时限定本项目镜像                                      |

不整目录盲删 `.dev-tools/`，也不将混有原始资料的工作目录全部视为缓存。失败现场在问题解决前保留，阶段完成后只保留必要的最终验收基线。node_modules 可重建，但日常格式和浏览器检查需要，可持续复用。

验收汇总以 `.dev-tools/test-results/release/validation.json` 为入口；浏览器、博客、字体和质量审计各保留自身当前报告。质量原始结果集中在 `quality/`，可复用质量审计逻辑维护在 `test/`，不依赖被忽略目录中的临时脚本。字体专项目录只保留覆盖、几何对照及其复查脚本、关键截图和必要基线，避免重复保存全站验收汇总。独立源码构建的源清单与证明集中在 `release/`，与当前候选清单分别标注；清理本身的文件清单和保护校验集中在 `maintenance/`，长期文档只更新阶段结论。

## 已完成的精简边界

演示项目／博客、模板媒体、模板文献、闲置 UI 分支、上游报告／截图、旧 Compose／Dev Container 和自动维护脚本已移除。不要恢复这些文件以满足过时测试；新增测试素材应置于隔离 fixture。

PCB／PI／SI 原稿归档、博客迁移原稿与校验记录、资源改名清单已按用户指定删除，不恢复。独立 `voice_terminal_site` 不再作为活动工程，仅保留上述私有源码归档。

`Gemfile`、锁文件、配置、模板和测试共同反映当前功能。清理插件前追踪实际消费者，保持 Scholar、目录、图像、公式、RSS 及逐页语言等有效能力。`footer.liquid` 的抑制覆盖、经典滚动条预留、主题和导航代码属于有效行为，不按“文件少”删除。

## 清理验收

修改前确认范围和必要输入；实施后执行正式构建、内部链接、受影响测试。依赖或公共模板／样式变化执行完整浏览器验收，并检查翻译与覆盖审计。比较真实内容和资产，避免改写用户已校对的描述、元数据或责任范围。

清理历史副本前完成当前验收，将最终结论并入相应开发阶段。详细命令输出和文件清单留在忽略的本地结果目录；长期文档保留稳定规则、阶段结果和仍待处理的事项。
