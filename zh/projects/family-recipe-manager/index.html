家庭菜谱与食材管理 App

兴趣
  • 项目时间：2026.02—2026.03
项目概述
独立开发微信小程序，结合大模型辅助菜谱导入、云端同步与家庭共享，连接备菜计划和烹饪后的食材库存更新。
项目方向
  • 软件工程
  • 移动应用
核心技术
  • JavaScript
  • Vue 3
  • 云函数计算
  • Tablestore
  • OSS

开发动机

菜谱收藏通常保留为链接或长文本，下厨前仍需重新整理食材与步骤、核对库存，并与家人协调当天的安排。项目希望减少这些重复操作，让分散的收藏能够直接用于家庭备菜。

目前已完成需求分析、前后端开发、交互与系统设计、大模型服务接入、云端部署和测试验证，以微信小程序供家庭试用。

主要工作

大模型辅助菜谱导入

支持用户输入菜谱链接或分享文案，通过云函数获取网页上下文并调用阿里云百炼的大模型接口，将外部信息整理为分类、食材、调料与步骤。模型输出由用户检查、补全并确认后入库。考虑到信息遗漏和请求中断，将解析结果保留为可恢复草稿，并提供手动录入入口，使自动整理与人工校正在同一流程中衔接。

云端存储与跨设备同步

将模型解析与菜谱管理划分为独立云函数，使用阿里云 Tablestore 保存菜谱记录、OSS 保存图片。以云端记录为准，本地缓存辅助读取，将新增、修改与删除的变更结果增量同步到缓存并刷新页面；离线时保留只读访问。围绕图片上传、记录保存与缓存刷新处理异步状态及失败反馈，衔接用户操作与云端数据结果。

库存建模与备菜联动

针对生鲜、整包食品与常备调料的记录习惯差异，设计数量与状态并存的库存模型：需要计量的食材记录数量，常备调料记录是否需要补充。将今日菜谱与库存关联，汇总备菜缺口；烹饪完成后，由用户检查并确认实际消耗，数量项按确认结果扣减，常备项保留提醒，避免要求所有食材都维护精确用量。

家庭权限与异常处理

完成用户系统，以家庭空间划分业务数据，设计邀请加入、空间切换、所有者转移等数据处理流程，并将成员权限与访问校验落实到服务端。将重复提交、离线访问、同步失败与会话失效纳入异常处理和回归验证，使成员变更与操作失败有明确的处理路径。

项目复盘

先梳理状态与失败路径

开发初期，解析、手动录入与确认入库的状态边界不清，曾出现连续解析受阻和加载状态无法退出的问题。通过明确状态迁移、拆分页面与业务编排职责，补齐超时与取消路径，并将异常场景纳入功能验收。

在可用性与同步复杂度之间取舍

根据家庭试用需求，优先保障断网查阅，将离线编辑与冲突合并留待后续。这一取舍减少了双端写入带来的状态组合，使数据一致性边界更清楚。

将真实环境联调前置

真实云端联调暴露了函数事件格式、数据库行结构和客户端接口兼容问题，增加了后期适配工作。将自动化回归与微信小程序端手工验收结合，逐段核对真实读写链路；后续应在扩展功能前验证部署环境与数据契约。
